# Технический roadmap проекта

## 1. Этап 1. Прототип и структура данных

### Цель
Создать базовый рабочий каркас продукта и зафиксировать минимальную структуру данных.

### Что делаем
- создать базовый frontend MVP;
- разработать структуру категорий и карточек офферов;
- задать базовые поля продукта и партнёра;
- подготовить данные для первой загрузки в каталог;
- сформировать правила статусов и обновлений.

### Результат
- работающий прототип с карточками и фильтрами;
- зафиксированные сущности: Partner, Offer, Category, Audit Log;
- минимальный набор данных для запуска.

## 2. Этап 2. Админка и управление контентом

### Цель
Сделать удобное управление каталогом без ручной правки кода.

### Что делаем
- создать административную панель;
- поддержать CRUD для партнёров и офферов;
- добавить статус публикации и управления данными;
- настроить хранение истории изменений;
- предусмотреть фильтрацию по категории и статусу.

### Результат
- можно добавлять, редактировать и скрывать офферы через админку;
- можно видеть историю обновлений;
- можно проверять актуальность и публиковать безопасно.

## 3. Этап 3. Автоматизация обновления данных

### Цель
Автоматизировать обновление условий, ссылок, комиссий и статусов.

### Что делаем
- настроить массив источников данных;
- добавить регулярную проверку актуальности условий;
- реализовать MARKER-логика: changed / old / out-of-date;
- добавить проверки на “битую ссылку”;
- логировать все изменения в audit log;
- ставить статусы: active, monitoring, paused, rejected.

### Результат
- уменьшение ручной работы;
- безопасное обновление офферов;
- снижение риска устаревшей информации.

## 4. Этап 4. Система сравнения и ранжирования

### Цель
Сделать каталог не просто списком, а системой сравнения и ранжирования.

### Что делаем
- определить формулу оценки;
- ввести критерии по комиссии, лимитам, рискам, удобству, KYC;
- добавить сортировку по выгодности;
- вывести рейтинг на главной и в карточках;
- сделать таблицу сравнения.

### Результат
- продукт становится полезным для пользователей;
- пользователь видит не просто список, а результат сравнения.

## 5. Этап 5. SEO и контент

### Цель
Поднять проект в поисковую видимость и увеличить органический трафик.

### Что делаем
- подготовить страницы категорий;
- создать статьи и сравнения;
- выставить структуру URL;
- сделать семантическое ядро по ключевым запросам;
- подготовить FAQ, обзоры и guides.

### Результат
- рост органического трафика;
- улучшение качества поиска и поведения пользователей;
- увеличение CTR на партнерские ссылки.

## 6. Этап 6. Монетизация и аналитика

### Цель
Перевести проект в доходный режим.

### Что делаем
- подключить рефералы и партнерские ссылки;
- добавить UTM-логирование;
- настроить события: клик, переход, конверсия;
- следить за CTR, отказами и доходностью;
- запускать A/B тесты для карточек и блоков.

### Результат
- видимость реального дохода;
- возможность оптимизации по эффективности партнерских связок.

## 7. Технологический стек (предварительно)

### Frontend
- HTML / CSS / JavaScript
- возможно: React или Next.js на более позднем этапе

### Backend
- Node.js / Express или Python / FastAPI
- база данных: PostgreSQL или SQLite для MVP

### Автоматизация
- Python scripts для проверки данных
- cron / scheduler / task runner
- JSON/CSV export для загрузки данных

### Storage
- PostgreSQL как основной вариант для стабильного роста
- SQLite допустим для локального MVP и лавинообразных экспериментов

## 8. Ключевой принцип проекта

Не копировать чужой портал визуально и текстово.
Сделать продукт, который:
- решает ту же бизнес-задачу;
- работает по похожей логике;
- но отличается дизайном, логикой ранжирования, наполнением и автоматизацией.

## 9. Результат первого цикла разработки

После первого цикла необходимо иметь:
- работающий MVP сайта;
- карточки офферов;
- работающую базу данных;
- проверку статусов офферов;
- структуру админки;
- лог обновлений;
- готовность к автоматизации и масштабированию.
