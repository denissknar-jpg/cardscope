# Анализ партнеров по виртуальным картам

## 1. Цель блока

Систематизировать и оценить партнёрские предложения по виртуальным картам, чтобы определить:
- какие партнеры подходят для MVP;
- какие условия реально выгодны;
- какие технические параметры можно автоматизировать;
- какие офферы стоит включать в каталог проекта.

## 2. Что нужно изучить у каждого партнера

### 2.1. Партнёрские условия
- тип программы (CPA, RevShare, CPL, Referral, Hybrid);
- размер комиссии;
- схема выплат;
- минимальный payout;
- условия активации лидов;
- ограничения по регионам;
- ограничения по трафику;
- требования к брендингу и рекламе.

### 2.2. Технические параметры
- наличие API;
- наличие affiliate API;
- поддержка UTM, clickid, subid;
- схема трекинга конверсий;
- cookie lifetime;
- тип линка для привлечения;
- требования к динамическим ссылкам;
- наличие статусов лидов.

### 2.3. Риски и ограничения
- правила финансовой рекламы;
- KYC и age restrictions;
- страна выдачи карты;
- риск изменений условий;
- риск вылета партнёра;
- риск блокировки рекламных каналов.

## 5. Критерии оценки партнёра

Оценивать каждую запись по шкале от 1 до 5:

- условия выплат — 1–5;
- прозрачность маркетинговых правил — 1–5;
- техническая совместимость — 1–5;
- стабильность оффера — 1–5;
- профиль риска — 1–5 (где 5 = высокий риск);
- удобство автоматизации — 1–5.

Формула оценки:

- Лучшая кандидатура = высокая прозрачность + высокая техническая совместимость + низкий риск.
- Отбор в MVP = средний или высокий балл по удобству интеграции и низкий риск по выплатам.

## 6. Что нужно собрать в первую очередь

Для первых 10–20 партнёров нужно получить:
1. правила партнерки;
2. структуру ссылок;
3. типы трекинга;
4. правила KYC;
5. ограничения на трафик;
6. условия выплат;
7. доступность данных через API или ручной экспорт.

## 7. Рекомендуемый порядок работы

### Этап 1 — разведка
- собрать список 10–20 партнёров;
- проверить, кто из них подходит по стране и продукту;
- проверить доступность оффера и маркетинговых правил.

### Этап 2 — техническая фильтрация
- определить, кто имеет API;
- кто требует manual approval;
- кто допускает автоматический трекинг;
- кто подходит для базового обновления ссылок.

### Этап 3 — отбор для MVP
- оставить 3–5 самых подходящих партнёров;
- сформировать базу офферов;
- настроить шаблон данных и логику обновления.

## 9. Что станет основой для автоматизации

- регулярная проверка актуальности условий;
- сравнение новой и старой версии оффера;
- блокировка устаревших ссылок;
- уведомление при изменении комиссии или статуса;
- логирование событий по каждому офферу;
- готовность к последующему экспорту в UI каталога.

## 10. Критерий “подходит для MVP”

Партнёр считается хорошим кандидатом для MVP, если:
- условия понятны и прозрачны;
- есть рабочая ссылка и трекинг;
- нет критических ограничений по трафику;
- есть возможность быстро встроить оффер в каталог;
- нет высокого юридического или технического риска.

## 11. Следующий шаг

Нужно перейти от таблицы анализа к реальной выборке партнёров и заполнить минимум 10 карточек в структурированном виде. Далее определим, кто из них попадёт в MVP и какие поля будут автоматически обновляться.
