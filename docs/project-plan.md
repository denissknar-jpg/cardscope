# Project Plan: Рейтинг-портал по финансовым продуктам

## 1. Цель проекта

Создать оригинальный маркетплейс/рейтинговый портал для сравнительного анализа финансовых продуктов и услуг. Проект должен быть удобен пользователю, эффективно монетизироваться через партнёрские ссылки и иметь встроенную систему обновления данных без постоянной ручной работы.

## 2. Основная идея продукта

Это не просто каталог, а система сравнения и ранжирования, где:
- пользователь видит актуальные предложения;
- видит преимущества и ограничения продукта;
- может быстро перейти по партнёрской ссылке;
- получает понятные и структурированные данные;
- видеть актуальность условий и обновлений.

## 3. Целевая аудитория

- пользователи, которые ищут выгодные карты, вклады и сервисы;
- клиенты, которым важно сравнить условия до оформления;
- аудитория, ориентированная на удобство и понятность.

## 4. Основные категории продукта

- виртуальные карты;
- дебетовые карты;
- кредитные карты;
- вклады;
- SIM-карты;
- оплата сервисов.

Не включаем:
- криптовалюты;
- криптобиржи.

## 5. Ключевые задачи

### 5.1. Бизнес-задачи
- подобрать подходящие партнерские программы;
- сформировать рейтинг продуктов по понятным критериям;
- обеспечить стабильную монетизацию через реферальные ссылки;
- создать понятную структуру для поискового трафика.

### 5.2. Технические задачи
- организовать базу данных по продуктам и партнерам;
- хранить условия, ставки, комиссии и ссылки;
- обеспечить логирование обновлений;
- автоматизировать обновление данных;
- строить систему проверки актуальности информации.

### 5.3. Контентные задачи
- подготовить страницы категорий;
- создать сравнение по ключевым критериям;
- сделать страницы обзоров и FAQ;
- обеспечить SEO-структуру и релевантный контент.

## 6. Принципы монетизации

- партнерские ссылки;
- реферальные офферы;
- блоки рекламы;
- спонсируемые разделы;
- коммерческие карточки и подборки;
- возможно: платные размещения в select-рубриках.

## 7. MVP-стратегия

### Этап 1. Запуск MVP

Выбрать первую категорию или 2 категории максимально быстро:
- виртуальные карты;
- вклады.

### MVP включает:
- главную страницу;
- категории;
- карточки офферов;
- базовую систему поиска и фильтрации;
- партнерские ссылки;
- базовую админ-панель для управления продуктами;
- минимальный механизм обновления данных.

### Этап 2. Расширение

После проверки спроса и прибыльности:
- добавить новые категории;
- внедрить более сложные фильтры;
- добавить сравнение по нескольким параметрам;
- усилить автоматизацию и улучшить SEO.

## 8. Рейтинг и критерии отбора

Для каждого продукта будут оцениваться параметры:
- комиссии и стоимость;
- размеры лимитов;
- надежность партнера;
- условия выдачи;
- скрытые ограничения;
- отзывы и репутация;
- удобство использования;
- прозрачность оффера.

## 9. Автоматизация

### Что автоматизировать
- сбор данных по партнерам;
- экспорт условий с сайтов;
- нормализацию данных;
- обновление статусов и ссылок;
- уведомления об изменениях;
- проверку сломанных ссылок;
- отслеживание устаревшей информации.

### Цель автоматизации

Сделать проект управляемым без постоянной ручной работы и снизить зависимость от “живого” редактирования каждого продукта.

## 10. Требования к архитектуре

### Frontend
- главное меню;
- списки и страницы категорий;
- карточки продукта;
- сравнительные таблицы;
- фильтры и сортировка;
- адаптивность под мобильные устройства.

### Backend
- админ-панель для редактирования продуктов;
- управление партнерами и офферами;
- управление ссылками и статусами;
- система логирования изменений.

### Data layer
- база данных партнеров;
- база данных офферов;
- история изменений;
- модель атрибутов продукта;
- хранение источников данных и дат обновлений.

## 11. Маркетинг и продвижение

- SEO-структура по ключевым категориям;
- обзоры и сравнения;
- информационные статьи и FAQ;
- тематические разделы с понятной навигацией;
- аналитика по кликам, CTR, конверсии и переходам.

## 12. Риски

- устаревание информации;
- разные условия по регионам и странам;
- несовместимость партнерских политик;
- сложность проверки источников данных;
- необходимость соблюдения правил финансовой рекламы.

## 13. Критерии успеха

- запуск рабочей версии проекта;
- функционирующая база данных по офферам;
- работа партнёрских ссылок;
- стабильный процесс обновления данных;
- высокая полезность для пользователя;
- начальная монетизация и рост трафика.

## 14. Следующий шаг по реализации

1. Определить MVP-категории.
2. Подготовить список партнеров для анализа.
3. Сформировать базовую структуру данных.
4. Разработать шаблон карточки продукта.
5. Начать проектирование админки и парсинга/автоматизации.
